# App 答题界面改造方案（全专业适配）

> 版本：v1.0　目标：解决"图小、图里塞文字、手机看不清"，用一套界面覆盖 78 个专业

---

## 0. 一句话方案

**图只画几何，文字全部由客户端排版；图占屏幕一半，点一下能全屏。** 所有专业共用同一套答题壳，差异只体现在题干区的"内容块"组合。

---

## 1. 现状问题

从实际截图看，当前图纸类题目有三个硬伤：

1. **图里混入了大段文字**。技术要求、说明、题目描述都画在图纸里，手机上一缩，字全糊了。
2. **图形被文字挤压**。题干、图、选项、按钮全在一屏抢空间，图只能分到很小一块。
3. **图不能放大**。尺寸标注、序号、剖面线在 360dp 宽的屏幕上无法辨认。

结论：不是图的问题，是**图与文字没有分离**，以及**图没有优先级**。

---

## 2. 三条硬规则

### 规则一：图内只放"图形语义"，不放题目

| 允许画进图里 | 禁止画进图里 |
|---|---|
| 轮廓线、剖面线、中心线 | 题目描述、题干 |
| 序号圆标（①②③④） | 选项文字 |
| 字母标注（A、B、C） | 解析、说明 |
| 尺寸数字（320、Ø80） | 技术要求、注意事项 |
| ≤4 字的短名称（曲柄、滑块） | 大段文字、表格文字 |

技术要求、图名、说明全部由客户端在题干区排版。教师上传的整张图纸，入库前必须裁掉标题栏和技术要求，只保留视图区域。

### 规则二：图优先占屏

- 图题模式下，图形区占屏高 **40%~55%**。
- 题干最多显示 **3 行**，超出折叠为"展开"。
- 保证首屏能看到完整图形，选项可以滚动查看。

### 规则三：一套壳，五种内容

顶部栏、选项区、底部操作栏所有专业完全一致。专业差异只通过题干区的内容块实现，不改布局。

## 3. 新界面结构

### 3.1 竖屏 · 图题模式（B 图纸式、A 符号式带图、D 数据式带表）

```
┌───────────────────────────────┐
│ ‹   单选题   3/15  [进阶] 02:14 │  56dp
├───────────────────────────────┤
│ 图示机构中，构件③的名称是：      │  3 行内
│                               │  展开 ∨
├───────────────────────────────┤
│                               │
│                               │
│         图形区                 │  40%~55% 屏高
│     （只含几何与短标注）         │  点按全屏
│                               │
│                      ⤢ 全屏    │
├───────────────────────────────┤
│ ○ A  曲柄                     │  56dp
│ ○ B  连杆                     │  56dp
│ ○ C  滑块                     │  56dp
│ ○ D  机架                     │  56dp
├───────────────────────────────┤
│ 草稿纸        不会        提交  │  72dp
└───────────────────────────────┘
```

**高度分配（360×640dp 小屏）**

| 区域 | 高度 | 说明 |
|---|---|---|
| 顶部栏 | 56dp | 不放多余信息 |
| 题干 | ≤72dp | 3 行，超出折叠 |
| 图形 | 260~320dp | 按图宽高比，上限 55% 屏高 |
| 选项 | 每个 56dp | 可滚动 |
| 底部 | 72dp | 固定 |

### 3.2 竖屏 · 文字题模式（C 流程式、E 文本式、纯文本题）

没有图形区，题干与材料可滚动，选项固定在下方或随页面滚动。图形区高度归零，题干最多可占 60% 屏高。

### 3.3 横屏 / 平板

- 宽度 ≥ 600dp：左右分栏，左侧图形（60%），右侧题干 + 选项（40%）。
- 工程图纸默认提供"横屏查看"入口，横屏时图更大。

### 3.4 全屏查看器

点图进入全屏：

- 双指缩放 1x~4x，双击放大，拖动平移，双击还原。
- 底部一行：图号 + 图名（由客户端渲染）+ 重置 + 关闭。
- 全屏背景用浅灰，图保持白底，不反色。

## 4. 图形规范

### 4.1 出图规格

| 项目 | 要求 |
|---|---|
| 格式 | SVG 优先，PNG 备用（2x/3x） |
| 最小宽度 | 1080px（对应 3x 屏） |
| 线宽 | 不小于 1.5px@1x，主轮廓 2px |
| 图内字号 | 不小于 12sp 等效，尺寸数字 11~12sp |
| 序号圆标 | 直径 ≥ 20px@1x |
| 背景 | 白底黑线，不加装饰 |
| 留白 | 四周至少 8% 安全边 |

### 4.2 图的来源（三层）

1. **资产库**：教师上传的图纸，入库前裁剪、去文字、切图。
2. **参数化模板**：机构简图、坐标系、电路符号、流程图、表格，由后端按参数生成。
3. **受限 DSL**：模型输出图元 JSON，服务端白名单渲染。

三层都不允许把题目文字写进图里。

### 4.3 图名与说明

- 图名由客户端渲染，放在图形下方一行，12sp 灰色。
- 技术要求、解析说明放在题干区或解析区，不贴在图里。
- 图号（图 1、图 2）由客户端根据题目顺序生成。

## 5. 五类模板的界面差异

| 模板 | 图形区 | 作答区 | 专属控件 |
|---|---|---|---|
| A 符号式 | 公式块，可无图 | 选项 / 填空 | 符号键盘（π √ ² ³ ∠ ℃） |
| B 图纸式 | 大图，40%~55% 屏高 | 选项为主 | 全屏、缩放、热点点击 |
| C 流程式 | 步骤卡，不是图片 | 选项为主 | 步骤编号、缺步标记 |
| D 数据式 | 表格 / 单据，可横向滚动 | 选项 / 填空 | 数字键盘 |
| E 文本式 | 无图或小图 | 选项为主 | 无 |

五类模板共用顶部栏、底部栏、选项卡片样式，只有中间内容区不同。

## 7. 交互规范

- **答题**：选择题点选项即选中；填空题点击输入框弹符号键盘；判断题两个大按钮。
- **翻页**：左右滑动，但图形区内的横向拖动优先给图片平移，避免误翻页。
- **草稿纸**：底部常驻入口，打开为全屏手写，可缩小为悬浮球。
- **反馈**：练习模式即时反馈；测评模式交卷后统一反馈。
- **加载**：图形先用骨架占位，加载完淡入，避免布局跳动。
- **失败**：图形加载失败显示"图 1 加载失败，点击重试"，不显示破图。

## 9. 验收标准

- 360dp 宽小屏上，图题首屏可见完整图形，无需滚动。
- 图形区高度不低于屏高 40%，全屏后可放大到 4x 仍清晰。
- 图内没有题目文字、选项、技术要求。
- 图名、说明由客户端渲染，字号不小于 12sp。
- 78 个专业切换，页面结构完全一致，只有内容区不同。
- 图形加载失败有兜底提示，不出现破图。
- 教师上传的图纸入库前已裁掉标题栏和技术要求。

## 10. 参考：Mobbin 教育类 App 的现行做法

来源：Mobbin iOS Education 分类（2026-11），重点看 Duolingo、Brilliant、Quizlet。

> 说明：免费账号每个 App 只能看前 4~8 张 screens，完整库需 Pro。以下结论基于可见的首屏页面。

| 观察到的做法 | 代表 | 对我们的改动 |
|---|---|---|
| 顶部分段进度条，不放多余信息 | Duolingo、Brilliant | 进度由"3/15"改为分段进度条 + 题号，难度徽标保留 |
| 题干 1~2 行，图形/交互区占最大空间 | Brilliant | 维持题干 3 行内、图 40%~55%，题干再压一档 |
| 主操作按钮固定底部、通栏 | Duolingo 的 CHECK、Brilliant 的 Check | 底部"提交"改为通栏主按钮，草稿纸和"不会"降为次要 |
| 反馈就地出现，不弹窗 | Brilliant 底部绿色面板"Correct! +15 XP" | 练习模式反馈改底部面板，图形保持可见 |
| 解析折叠成一个入口 | Brilliant 的 "Why?" | 解析默认收起，点"为什么"展开，不默认铺长文 |
| 图形区本身可交互 | Brilliant 网格编程 | 图纸题的热点直接可点选，与 ABCD 选项联动高亮 |
| 单一主色 + 中性底，不堆彩色 | Duolingo 绿、Brilliant 绿/黑 | 保持黑/蓝主色，选项不加彩色 |
| 进度有"段"的感觉 | Duolingo 生命值、Brilliant 闪电 | 我们不用生命值，用难度档位替代 |

**三条可以直接抄的**

1. 顶部只留：关闭、分段进度、当前题号。
2. 底部只留一个通栏主按钮，其余动作收进次级位置。
3. 答对/答错用底部面板反馈，不要把题目盖住。

**两条不适用**

- Duolingo 的"生命值/连胜"是游戏化留存手段，中职测评场景会干扰成绩判断，不做。
- Brilliant 的图形拖拽作答需要专门的判分逻辑，我们只有选择/判断/填空，图形区只做"展示 + 热点联动"，不做拖拽作答。
