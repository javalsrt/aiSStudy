# Spec：管理端系统功能测试用例与执行手册

## 1. 背景与目标

用户需要一份可直接交给其他大模型执行的**管理端（web-admin-react）系统功能测试文档**，要求覆盖「测试执行 → 问题记录 → 测试报告」三阶段，并尽可能详细。

本 Spec 定义该文档的范围、结构、验收标准与执行约束；实际交付物为：

`docs/管理端系统功能测试用例.md`

## 3. 关键决策

1. **交付物单一主文件**：所有用例、缺陷模板、报告模板、LLM 提示词集中在 `docs/管理端系统功能测试用例.md`，避免执行者跨文件拼装。
2. **每条用例独立小节**：固定字段为「优先级 / 前置数据 / 操作步骤 / 预期结果与断言 / 验证方式 / 证据要求 / 清理复位 / 判定」，另保留 4.0 索引表。
3. **三阶段门禁**：P0 未 100% 通过不得出具「通过」结论；S1/S2 遗留不得发布。
4. **数据安全**：只允许使用 `qa_` 前缀测试数据；测试前 `mysqldump` 基线备份；禁止删除 admin、当前学期、预置课程。
5. **AI 依赖单独判定**：AI 服务不可用时标记 BLOCKED，不计 FAIL。
6. **报告结论三选一**：通过 / 有条件通过 / 不通过，依据第 6.3 节标准。
7. **执行证据规范**：截图、HAR、接口响应、SQL 结果、后端日志五类，统一存 `test-artifacts/YYYYMMDD/`。

## 5. 交付物验收标准

| 验收项 | 标准 |
|---|---|
| 文件存在 | `docs/管理端系统功能测试用例.md` 可打开 |
| 结构完整 | 含 0–8 章：阅读顺序、范围、环境、执行规范、详细用例、缺陷记录、报告撰写、LLM 提示词、附录 |
| 用例可执行 | 每条为独立小节，含前置数据、编号步骤、勾选断言、验证方式、证据要求、清理动作、判定口径；编号唯一 |

| 报告可套用 | 含完整 Markdown 报告模板、统计公式、结论标准、交付命名 |
| 可直接交给大模型 | 第 7 章含可复制的角色、规则、输出格式、停止条件 |
| 附录可用 | API 清单、只读 SQL、15 分钟冒烟清单、术语表 |
| 安全约束 | 禁止生产写操作、QA 数据前缀、基线备份说明 |

## 6. 风险与待确认

| 风险 | 影响 | 应对 |
|---|---|---|
| 教师/学生测试账号可能不存在 | 权限用例阻塞 | 管理员先创建 `qa_teacher_01` / `qa_student_01` |
| AI key / 向量服务未启动 | 导入、出题、章节生成用例 BLOCKED | 启动 8000 服务并配置 key；否则标记 BLOCKED |
| 数据库表名/字段与附录 SQL 不一致 | 核对 SQL 报错 | 执行前 `DESC 表名` 校准，不据此判缺陷 |
| 测试数据残留 | 污染后续测试 | 测试后用 UI 删除 `qa_` 数据，并记录 cleanup |
| 当前学期被误切换 | 影响课表/排课用例 | 基线记录当前学期，结束时切回 |

## 7. 执行与审批

- 文档已生成，等待用户确认后再进入实际测试执行。
- 执行阶段使用 `docs/specs/admin-system-test/tasks.md` 跟踪进度。
- 用户可使用其他大模型按第 7 章提示词执行；本 Spec 不涉及代码改动。
