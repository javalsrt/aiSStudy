# aiStudy 差距分析：对照成熟教务系统，差点什么

> 分析对象：`backend`（Spring Boot 3.2 + MyBatis-Plus）、`web-admin-react`、`miniapp`、`android`
> 方法：以代码事实为准（entity / controller / service / 路由 / SQL），不采信文档自述。凡"文档说有、代码没有"的，单列说明。
> 结论口径：**已具备 / 部分具备 / 缺失 / 有表无码 / 有码无端**。

---

## 0. 结论摘要

1. **定位判断**：这不是"教务系统"，是"**排课 + 学习过程管理**"平台。教务主干（选课、成绩、学籍、培养方案、考务、评教）几乎全空；AI 与学习过程侧反而强于多数传统教务。
2. **四个结构性缺口**：① 没有"教学班"，所以没有真正的选课；② 成绩链路断裂，考试分不进总评；③ 考勤是"有后端、零前端"的孤儿模块；④ 治理层有三张空表（数据权限、通知、审计）。
3. **六层评分 14.5 / 30**：L1 业务闭环 1.5、L2 架构与峰值 3.0、L3 数据贯通 2.0、L4 智能化 3.5、L5 体验 3.0、L6 治理与生态 1.5。
4. **最讽刺的一点**：在"导出、审计、通知、审批流、数据权限"这些传统教务系统都有的治理项上，本项目比传统系统还弱。
5. **最高性价比四件事**：教学班+选课最小闭环、课程成绩册（权重→总评→绩点）、考勤闭环、报表导出。不建议补招生/学籍异动/培养方案/排考/评教。

## 1. 六个结构性发现（先看这个）

### 1.1 没有"教学班"，`course` 直接挂教师，`schedule` 按学生存

| 事实 | 证据 |
|---|---|
| `Course` 直接持有 `teacherId`、`semester`、`credit` | `backend/.../entity/Course.java:20-32` |
| 有 `course_class`（课程 ↔ 班级 ↔ 学期）"开课关系"，但**无教师、无容量、无时间、无选课记录** | `backend/.../entity/CourseClass.java:10-21` |
| `Schedule` 以 `userId + courseId` 存储，并冗余 `courseName` | `backend/.../entity/Schedule.java:17-22` |
| 课表导入按"学生 × 周"逐行插入 | `ScheduleImportController.java`（confirm 阶段拆行写入） |
| 全库无 Section / Enrollment / 容量 / 候补 任何实体 | `entity/` 33 个实体逐个核对 |

**后果**：一个 40 人班 = 40 行课表；换教师 = 改课程；换学期 = 复制课程；同一门课开两个班无法表达；"选课"在数据模型上不存在，只能由管理员/导入"指派"。

注意：`course_class` 容易被误认为"教学班"，但它只是"某学期某课程开设给哪些行政班"，教师仍挂在课程上，没有容量、没有时间、没有学生选择行为，因此不能承担选课、成绩册、考勤的归属。

这不是实现问题，是**模型缺一层**。成熟系统的三层是：`Course`（课程目录）→ `Section`（教学班：学期+教师+容量+时间）→ `Enrollment`（选课关系）。

### 1.2 `credit` 被挪用成"周课时上限"

- `Course.credit` 注释是"学分"（`entity/Course.java:31`）。
- 但 `TeacherClassController.updateCourseCredit` 的注释与实现是"**每周课时上限**"，范围 1~20（`:76-110`）。
- 全库没有绩点、总评、学分绩点计算。

**后果**：字段语义冲突，未来真要做学分/绩点时必须迁移；现在系统里"学分"这个词是不可信的。

### 1.3 成绩链路断裂：单次分数，没有课程总评

| 已有 | 缺什么 |
|---|---|
| `ExamSubmission.totalScore` 单次考试总分（AI 分 + 教师逐题调分） | 课程总评、权重、绩点、班级成绩册 |
| `QuizSession.scores` 六维能力分 0-10 | 分数不进任何总评 |
| `TeacherStatsController` 用 `AVG(total_score)` 展示 | 无排名、无及格率、无成绩单 |

**后果**：教师无法出一门课的期末总评；学生查不到"我这学期成绩"；统计页只能看单次考试记录。这是"教学"闭环的最后一公里，缺了它，前面所有过程数据都无法结账。

### 1.4 考勤：后端 4 个接口，四端 0 调用

- `CheckInController` 有 `create / verify / status / close` 四个端点（`:31/75/115/140`），教师设口令、15 分钟有效、`INSERT IGNORE` 幂等。
- 全仓搜索 `check-?in|checkIn|签到`，**除后端 4 个文件外，前端零命中**。
- 没有迟到/缺勤/早退判定，没有应到人数、出勤率、请假、补签；`check_in` 只挂 `course_name` 字符串，不关联课表/节次/班级。

**后果**：功能实际不可达。这是典型的"写完接口就以为做完了"。

### 1.5 治理层有三张空表

| 表 | 现状 | 代码引用 |
|---|---|---|
| `sys_data_permission`（ALL/DEPT/CLASS/SELF） | 建表、自增到 40、**0 条记录** | 0 处 |
| `notification` + `notification_receipt` | 建表、**0 条记录** | 0 处（仅一个方法名含 notification） |
| 审计日志 | 无表、无 `@Aspect`、无拦截器 | — |

同时：限流只作用于 LLM 调用（`LlmService`），幂等只覆盖调课与课表导入两处，`app.redis.enabled` 默认 `false`（`application.yml:76`），WebSocket 是进程内 Map（多实例不互通）。

**后果**：多院系/多班场景下，教师 A 能查教师 B 的数据只能靠逐个接口的归属校验兜；出了问题无法追溯。答辩问"权限怎么做的"，只能答到"注解 + 角色"，答不到"数据范围"。

### 1.6 排课规则表是"死表"

- `ScheduleRule` 字段齐全：课程类型、科目、偏好时段、偏好教室类型、连堂、优先级加权（`entity/ScheduleRule.java:23-45`）。
- 但 `AutoScheduleService` **没有注入该 Mapper**，全库只有 entity + mapper 两个文件引用它。
- 实际算法是**单遍贪心**，不是注释里写的"贪心 + 回溯"：失败即记 `failed`，不回退已排任务（`:176-197`、`:250-259`）。

**后果**：教务员改了规则不生效，且无从发现——这比"没有规则配置"更糟。

## 2. 六层能力盘点

### L1 业务闭环与规则可配置 — 1.5 / 5

| 能力 | 判定 | 说明 |
|---|---|---|
| 课程目录维护 | 已具备 | 课程上下架、删除、章节/课时 |
| 排课/课表 | 已具备（有模型缺陷） | 自动排课 + 周视图 + 作息表 + 锁课 |
| 选课/退课/容量/候补 | 缺失 | 无实体；靠导入指派 |
| 成绩/绩点/成绩单 | 缺失 | 仅单次考试分 |
| 学籍/异动/培养方案/毕业审核 | 缺失 | 无实体、无字段 |
| 考务（考场/监考/排考） | 缺失 | 无 |
| 评教/教学工作量 | 缺失 | 无 |
| 规则引擎 | 部分（假象） | 有表不生效；无版本管理 |

### L2 架构与峰值稳定性 — 3.0 / 5

**做得好**：Spring Boot 分层清晰、JWT + BCrypt + 单设备登录、全局异常、Actuator + Prometheus、graceful shutdown、Hikari/Redis 连接池已配、Redis 幂等与 Lua 限流骨架、课表导入 64 桶串行锁。

**差什么**：无 MQ（AI 出题/导入仍同步）、限流只覆盖 LLM、幂等只覆盖 2 个入口、Redis 默认关闭、WebSocket 单机、无慢 SQL 治理（虽有 slow log 配置）、无缓存层（课程/课表高频读直接打库）。

选课这种"余量争抢"场景不存在，所以当前架构还没被真正压测过——一旦做选课，行锁问题会立刻出现。

### L3 数据贯通 — 2.0 / 5

**做得好**：课程→章节→课时→进度 一条线是通的；考试→提交→逐题调分是通的；聊天/通知共用 `chat_message` 且带未读计数。

**差什么**：
- 课程与排课、考勤、成绩之间靠 `course_name` 字符串弱关联（`check_in.course_name`、`schedule.course_name`），改名即断。
- 无统一主数据（院系表 `department` 存在但无实体；`user.major/grade` 是自由文本）。
- 数据权限未落地，跨模块查询各自写归属校验。
- 过程数据（专注、刷题、章节进度）沉淀充分，但**缺少成绩与学籍维度，无法形成学生档案**。

### L4 智能化 — 3.5 / 5

**强于多数传统教务**：RAG 答疑、AI 出题（按范围/文档）、错题分析、六维能力评分、AI 识别课表文件导入、题库预热。

**差什么**（教务域）：
- 无学业预警（有数据、无模型、无触发动作）。
- 无智能排课优化（规则表空转）。
- 无教务政策问答（RAG 只覆盖课程文档）。
- 无 AI 辅助审题/审核成绩异常。

结论：AI 是差异化优势，但目前集中在"学"，不在"教/管"。

### L5 体验 — 3.0 / 5

**做得好**：管理端有 loading/error 分支、shadcn 组件统一、图表完整、课程群聊 @点名、文件上传。

**差什么**：
- 零导出、零批量选择（`@tanstack/react-table` 装了但没用于勾选批处理）。
- 小程序把网络错误显示成"暂无课程"（`pages/index/index.vue:67-69`）；课表请求失败静默吞掉（`pages/schedule/index.vue:138`）。
- 管理端原生 `confirm/alert` 与自有弹窗混用（`exam-homework.tsx:408/413/461/467`）。
- 无通知中心，只有教师端一个未读气泡。
- 小程序是 Android 的严格子集：签到、作业、章节学习、专注计时、错题本全缺。

### L6 治理与生态 — 1.5 / 5

| 项 | 状态 |
|---|---|
| RBAC 表驱动 + 方法级注解 | 已具备（但 90% 只用 `hasRole`，细粒度权限码仅 1 个 Controller） |
| 数据范围（DEPT/CLASS/SELF） | 有表无码 |
| 审计日志 | 缺失 |
| OpenAPI/Swagger | 缺失（pom 无依赖） |
| CI/CD | 缺失（无 `.github`，测试不自动跑） |
| 测试 | 3 个类 12 个 Mock 单测；排课/冲突/鉴权/考勤/评分均无测试 |
| 安全配置 | compose 明文 root 密码 + JWT secret；CORS `*`；无 HTTPS |
| 部署 | Docker Compose 完整（mysql/redis/backend/nginx/embedding），有健康检查 |

## 4. 优先级建议

### A 档：值得做，且能讲清技术含量

| # | 事项 | 最小落地范围 | 验收标准 | 成本 |
|---|---|---|---|---|
| A1 | **课程-教学班-选课最小闭环** | 把 `course_class` 升级为 `section`（补 `teacher_id`/`capacity`/`status`/周次），或新增 `section` 表；新增 `enrollment`（学生/状态）；课表改挂 `section_id`；选课前置校验（容量、时间冲突、已选）；退课 | 40 人班只有 1 条排课；学生能选/退；冲突有中文原因；余量并发不超卖 | 高 |
| A2 | **课程成绩册** | `course_grade`（学生/教学班/平时/期末/总评/绩点）+ 权重配置 + 从考试/作业汇总 + 成绩单导出 | 教师一键生成总评；学生可查学期成绩；导出 Excel | 中 |
| A3 | **考勤闭环** | 教师端发起签到（关联节次/教学班）+ 学生端入口 + 应到名单 + 迟到阈值 + 出勤率 | 四端可达；出勤率可算；缺勤名单可导出 | 中 |
| A4 | **修小程序聊天 GET 误发** | `chat/index.vue:106/113/131` 改用 `utils/api.js` 的封装方法 | 发消息/问 AI/已读三个请求带 body 且方法正确 | 低（小时级） |

> A1 是 A2/A3 的前置：不先有"班"，成绩和考勤都只能挂在字符串上，做两次返工。

### B 档：加分项，能讲"治理"

| # | 事项 | 说明 |
|---|---|---|
| B1 | 数据权限落地 | 用现成 `sys_data_permission` + MyBatis-Plus 拦截器，按 DEPT/CLASS/SELF 注入 where 条件 |
| B2 | 审计日志 | `@Aspect` 记录操作人/资源/前后值/IP，落 `operation_log` |
| B3 | 调课审批流 | `schedule_adjust_request`（pending/approved/rejected + 审批人），替代当前"直改 + 加锁" |
| B4 | 通知中心 | 启用 `notification` 表 + 未读回执 + WS 推送，替代"借用 chat_message" |
| B5 | 排课规则生效 | `AutoScheduleService` 读取 `ScheduleRule`，失败时给替代时段建议 |
| B6 | 报表中心 | EasyExcel/POI 导出成绩单、考勤表、课表、班级名册 |
| B7 | 全站限流 + 幂等 | 网关/拦截器层，不再只保护 LLM |
| B8 | OpenAPI + CI | springdoc + GitHub Actions 跑 `mvn test` / `npm build` |

### C 档：明确不做，写进"范围声明"

招生录取、学籍异动全流程、培养方案与毕业审核、排考与考场编排、评教、财务对账。

理由：合规与流程复杂度高、与职校实际场景弱相关、答辩不加分，且会把"AI 学习平台"的特色稀释成"半成品教务系统"。

## 5. 答辩叙事建议

不要说"我做了一个教务系统"——一对比就露。建议表述：

> "面向职业院校的**教学运行与学习过程平台**：以排课为骨架，以学习过程数据（章节进度、专注、测评、错题）为血肉，用 AI 把过程数据转成教学决策。"

配套强调三个技术点（都有代码支撑）：
1. **可解释的排课冲突检测**：四维位图 + 中文冲突原因 + 锁课硬约束。
2. **非结构化课表导入**：xlsx/docx/pdf/txt 直解 + LLM 兜底 + 教师模糊匹配 + 幂等串行。
3. **过程性评价**：六维能力分 + 错题分析 + 复习计划，而不是"一次考试定成绩"。
